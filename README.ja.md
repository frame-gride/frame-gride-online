# frame-gride-online

[English](README.md) | 日本語

ドリームキャスト『フレームグライド』（フロム・ソフトウェア、1999年、`T34201M`）の「NET GAME」（2人でのオンライン対戦）を、エミュレーターの [Flycast](https://github.com/flyinghead/flycast) で遊べるようにするための、**非公式**のファン制作です。調べた内容、ツール、単独で動くサーバーをまとめています。ディスクイメージは改造しません。

> **2026-11-20の更新: フレームグライドが、Flycast の DCNet でオンラインになりました。** Flycast の作者が、このゲームを DCNet に加えました（[Discussion #2621](https://github.com/flyinghead/flycast/discussions/2621)、コミット [`460a821`](https://github.com/flyinghead/flycast/commit/460a821)）。この変更は Flycast の master ブランチに入っていて、**2.7 の正式版には入っていません**。[Flycast のビルドのページ](https://flyinghead.github.io/flycast-builds/)から、新しいビルドを使ってください。このリポジトリのサーバーは、遊ぶためにはもう要りません。参考と予備として残しています。

ゲームと Flycast には、手を加えていません。ゲームのデータも含めず、配布もしません。

> このプロジェクトは、フロム・ソフトウェア、セガ、Flycast の開発者とは関係ありません。

## DCNet でオンライン対戦する

1. 自分で用意した『フレームグライド』（日本版、`T34201M`）のディスクイメージを用意します。
2. [ビルドのページ](https://flyinghead.github.io/flycast-builds/)から、新しい Flycast（master）を入れます。2.7 の正式版は、このゲームをまだ知りません。
3. Flycast の設定の Network タブで、DCNet を有効にします。設定（エミュレートしているモデムの ISP の項目を含む）は、[Flycast の wiki の DCNet のページ](https://github.com/TheArcadeStriker/flycast-wiki/wiki/DCNet)にあります。
4. ゲームを起動し、下の「[ゲームでの操作](#ゲームでの操作net-game)」に進みます。

通信の遅延が大きいと、ゲームの限界（[動作状況](#動作状況)を参照）を超えて、遊べなくなります。DCNet のサーバーまでの遅延が小さいほど、遊びやすくなります。

## ゲームでの操作（NET GAME）

1. タイトル → NET GAME → 名前を入力 → ダイヤル（A）→ サーバーの選択（A）→ ニックネームの確認（A）の順に進みます。これでロビーに入れます。
2. プレイヤー1は、START → チーム作成（A を押し、続けて A、A、START）。プレイヤー2は、START → 下 → A → 参加の確認（A）。
3. プレイヤー1は、チームルームで START → PLAY（A）。2人とも対戦に入ります。

この手順は、このプロジェクトの自作サーバーで確かめたものです。DCNet でも、同じはずです。

通信対戦では、遅延を加えなくても、オフラインの対戦よりボタンを押してから動くまでが約10フレーム（約170 ms）遅くなります。詳しくは [docs/MEASUREMENTS.md](docs/MEASUREMENTS.md)（英語）にあります。

## セーブデータの全解放

まず、カードにセーブデータがある必要があります。ストーリーモードを一度始め、名前を入力してセーブしてください。そのあと、Flycast を閉じてから次を実行します。

```
uv run python unlock_all.py T34201M_vmu_save_A1.bin unlocked/T34201M_vmu_save_A1.bin
uv run python vmu_tool.py unlocked/T34201M_vmu_save_A1.bin
```

`T34201M_vmu_save_A1.bin` は、Flycast のデータフォルダにある、メモリーカード（A-1）のファイルです。ツールは結果を別のファイルに書き出し、元のファイルを上書きしません。それでも、元のファイルの控えは取っておいてください。`vmu_tool.py` を実行して `CRC ok` と表示されれば、ファイルは正常です。

戦績は、指定しない限りそのまま残ります。`--wins` で勝ち数、`--losses` で負け数を、それぞれ0〜9999の範囲で指定できます（例: `--wins 9999 --losses 9999`）。1P、VS、NET、トータルの4つの戦績すべてに同じ値が入り、戦数は勝ち数と負け数の合計になります。合計が9999を超えるときは、戦数は9999になります。片方だけ指定した場合、もう片方はセーブの値のままです。`--max-records` を付けると、9999戦0敗9999勝になります。負け数を入れた戦績は、ファイルの中身では確かめましたが、ゲーム画面での表示はまだ確かめていません。

書き出したファイルを、Flycast のデータフォルダに置き直します。NET GAME で解放した機体を使うには、チームルームで START → 騎兵設定 → 記 録 → ロード → セーブを選ぶ → B → 設定終了 の順に操作します。セーブの形式は [docs/SAVE_FORMAT.md](docs/SAVE_FORMAT.md)（英語）にまとめています。

公開のサーバーでは、ほかのプレイヤーにも、あなたの機体と戦績が見えます。解放や戦績のオプションは、そのことを考えて使ってください。

## 自分でサーバーを動かす（任意）

ここにある Python のコード（標準ライブラリだけ）は、昔のゲームサーバーの役目を、単独で果たします。LAN での対戦、試験、そしてゲームの通信を知るための参考として役に立ちます。

- `modem_bridge.py` と `ppp_engine.py`: Flycast の DCNet（エミュレーターのモデム通信を外のサーバーへつなぐ機能）を受けるサーバーです。ゲーム機のダイヤルアップに応答してアドレスを割り当て、2台のゲーム機のあいだで通信を中継します。
- `lobby_probe.py`: ゲームのロビー（UDP 9500/9501）を再実装したものです。ニックネーム、ロビーの一覧、チーム、対戦開始（PLAY）を扱います。
- `unlock_all.py` と `vmu_tool.py`: 上で説明したセーブのツールです。

Python 3 が要ります（3.14で動作を確認）。例では [uv](https://docs.astral.sh/uv/) を使っていますが、`python` コマンドでも動きます。

### 1台のPCで試す（Flycast を2つ起動）

1. ロビーとブリッジを起動します。ターミナルを2つ開き、それぞれで次を実行します。

   ```
   uv run python lobby_probe.py
   uv run python modem_bridge.py --mode ppp --vj asymmetric
   ```

2. それぞれの Flycast の設定ファイル `emu.cfg` で、`[network]` の節を次のようにします。

   ```
   DCNet = yes
   DCNetServer = 127.0.0.1
   ```

   1台のPCで2つ起動するときは、2つの Flycast で、データフォルダ、`LocalPort`、`ISPUsername` をそれぞれ別の値にします（例: `flycast_p1` と `flycast_p2`）。

3. 「[ゲームでの操作](#ゲームでの操作net-game)」のとおりに遊びます。

### 2台のPCで遊ぶ

ロビーとブリッジは、どちらか1台（ホスト）で動かします。ブリッジは、外のPCからの接続も受け付けるように起動します。

```
uv run python modem_bridge.py --mode ppp --vj asymmetric --host 0.0.0.0
```

もう1人は、自分の Flycast の `DCNetServer` に、ホストのPCのアドレスを書きます。ホストで、外のPCから接続できるようにしておく必要があるのは、TCP の 7654番ポートだけです。ホストのファイアウォールで、このポートを許可してください。インターネット越しに遊ぶ場合は、ルーターのポート開放（外からの接続をホストのPCへ転送する設定）か、Tailscale のような VPN（離れたPCどうしを同じネットワークにつなぐサービス）が要ります。ロビーはホストの中で動かしたままで構いません。ゲーム機からロビーへの通信は、ブリッジがホストの中で受け渡します。

PCどうしの通信の遅延は、そのままゲーム機どうしの遅延になります。「動作状況」にある限界を超えないよう、ホストは、なるべく近くの人が受け持ってください。

### 試験用のオプション

`modem_bridge.py` には、ゲーム機どうしの通信に遅延、ゆらぎ、パケットロスを加えるオプションがあります。1台のPCで、遠くの相手と遊ぶ状況を再現するためのものです（`--p2p-delay-ms`、`--p2p-jitter-ms`、`--p2p-loss-pct`、`--p2p-seed`）。ロビーとブリッジは、スクリプトと同じフォルダに JSON Lines 形式のログを書きます（`lobby-probe.jsonl` と、`modem-capture.jsonl` または `--log` で指定したファイル）。

## テスト

```
uv run python -m unittest discover
```

テストのうち2件は、環境変数 `FG_SAVE_IMAGE` に実際のメモリーカードのファイルを指定したときだけ動きます。指定がなければ省かれます。
